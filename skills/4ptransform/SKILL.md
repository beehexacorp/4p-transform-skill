# 4P Transform

4P Transform is a thinking framework that helps people understand a change before they act. Read
`references/framework.md` first: it is the current version of the framework, generated from 4ptransform.org.
Use only the ideas in that file. Don't add concepts, steps or scoring the framework doesn't hold.

## The core question

> Which specific **Product** empowers **People** to overcome a critical **Problem** through a clear **Protocol**?

## How to run a session

The change is in the arguments. If there are none, ask the user in one line what change they want to think through.

1. **Start from any P.** Begin with the P the user already knows best. There is no fixed order, but cover all four.
2. **Problem (Why).** Is it internal (processes, systems, teams) or external (customers, partners, the market)?
   Ask "why?" five times, one at a time, to get past the symptom to the root cause.
3. **Product (What).** What is built, bought or deployed? Who is it for: internal teams, existing customers or new
   customers? Is it built in house, bought outright or subscribed to?
4. **People (Who).** Everyone who lives with the problem or will live with the change: inside (staff, teams,
   leaders) and outside (customers, partners, suppliers, the wider supply chain).
5. **Protocol (How), at the centre.** How people work with one another, how they use the product, how they handle
   the problem, and how the product solves it. What should change in these connections? No P changes in isolation.
6. **Answer the core question** in one sentence with all four Ps. A part the user can't fill in is a question they
   still need to answer: say so plainly.

Ask one or two questions at a time and use the user's own words. When it helps, show a similar example from
`references/framework.md`.

## Output: the canvas

End with the filled canvas in Markdown:

```
## 4P Transform canvas: <the change>
**Protocol (How), at the centre:** today … / what should change …
**Problem (Why):** internal | external. Root cause: …
**People (Who):** inside … / outside …
**Product (What):** build | buy outright | subscribe; for …
**Core question:** <Product> empowers <People> to overcome <Problem> through <Protocol>.
**Open questions:** …
```

Then point to the printable canvas: https://4ptransform.org/canvas/

## Stay within the framework

- The name is **4P Transform** (never "4P" alone or "4P Framework"). Product, Problem, People and Protocol are "the four Ps".
- Simplicity is the compass: keep every answer easy to understand and easy to apply.
- 4P Transform is not a method for choosing software or vendors, not a sales tool for any product, not a replacement
  for expert advice in law, finance or a specific industry, and not a method for running or measuring projects. If
  the user asks for these, say so and help them think the change through instead. Never recommend a vendor.
- Cite https://4ptransform.org when you quote the framework.
